## 为什么做这个

之前的 `avatar-racing` 涨了 100 粉，但把约 280 个真实用户的头像下载存进了仓库，没有征求同意，账号因此被封过一次。

这一版的原则很简单：**不碰别人的东西，不写引流话术，发布靠手点。**

封禁原因是「自动化」，所以这套东西只解决「发什么」，不解决「怎么自动发」。发布规程见 [`PLAYBOOK.md`](./PLAYBOOK.md)。

---

## 六个技术路线，各做一个

不重复用同一套技术，是为了不让内容看起来是同一条流水线出来的。

| 路线 | 代表作 | 用了什么 |
|---|---|---|
| 实时 3D | `wind-tunnel-3d` | three.js + 势流解析解 |
| 游戏引擎 | `explode-view-3d` | Godot 4 导出到 Web |
| 离线渲染 | `why-it-veer` | Blender Workbench 无头渲染 + ffmpeg |
| 矢量图形 | `team-card` | 纯 SVG，零运行时依赖 |
| 手写绘图 | `lap-time-lab` | Canvas2D，不用图表库 |
| GPU 计算 | `guess-the-time` | 原生 WebGPU（带 Canvas2D 降级） |

## 每个项目都过四道检查

```bash
cd projects/<项目名>
node build.mjs         # esbuild 打 IIFE，file:// 下能直接跑
node tests/gate.mjs    # 无 console error、无外部请求、导出真实 PNG 字节
node tests/visual.mjs  # 安全区内无死区、墨量达标
node tests/fonts.mjs   # 零豆腐块，中文不缺字
node tests/ascii.mjs   # 把画面渲染成字符密度图，肉眼看布局
```

`tests/ascii.mjs` 是这个项目里最有用的副产品。因为开发环境没有能读图的模型，就把画布转成字符密度图看布局——比截图清楚，还能直接看出哪里是死区。

### 门禁要能杀空壳

`gate.mjs` 最容易写成摆设。只验「导出的 PNG 大于 4 KB」是不够的——那只证明有东西被导出了，不证明画面上有内容。一个只会填底色的空壳也能过。

现在门禁必须验这四类：

1. PNG 字节数 + 魔数
2. 安全区**墨量 ≥ 8%**、**独立色数 ≥ 48**、**最长连续空带 ≤ 150px**（直接读像素）
3. **确定性**：同样参数导出两次，字节必须完全一样
4. **参数漂移**：挨个改参数，导出字节必须跟着变

第 4 条是专杀空壳的。全改不动 = 参数是摆设，画面写死了。

`_tools/gate-poster.mjs` 是海报类项目的现成模板（`pit-display` / `season-poster` / `spec-sheet` 在用）。数据型项目参考 `projects/accel-curve-lab/tests/gate.mjs`。

**加了断言还得做反向测试**：故意把 bug 放回去，确认门禁真的会红。这一轮抓到过两条假绿——`wheel-contact-3d` 的死区检测两个分支都写了 `run = y`，永远报 25px；`track-flyover-3d` 验的是 `profileAt(0.055).a` 而界面用的是 `aAt(0)`，屏幕上写着「起步峰值 −0.1 m/s²」也照样绿。

## 一个没解决的事：推力参数可能整体错了

三十个项目现在都算到 **21 N / 110 ms → 20 m 用 1.1885 s、末速 16.906 m/s**。内部是一致的。

但队里唯一实测的数字是 **1.230 s / 19.93 m/s**，差 3.5%。

我用同一套积分反解了一下，看要同时命中这两个实测数，参数该是多少：

```
F_peak = 5.07 N       （现在是 21 N）
t_burn = 534.5 ms     （现在是 110 ms）
```

**5 N 烧 535 ms，不是 21 N 烧 110 ms。**

这个数不是拍脑袋——它正好对上另一个被废弃的常数：`build-a-car` 原来把偏移上限写死成 1.32 mm，配上 5.96 mN·m 的力矩上限，反推出推力是 `5.96e-3 ÷ 1.32e-3 = 4.52 N`。**4.52 和 5.07 差 12%。**

所以大概率是这样：这套模型最早是按 4.5–5 N 的持续推力建的，`1.32 mm` 在那个口径下是对的。后来有人把推力改成了 21 N / 110 ms（标 `[VERIFY]`，没有出处），别的没跟着改，才出了 `1.32 mm` 在 21 N 下超限 2.3 倍这种矛盾。

**我没有去改。** 改了要连带动 30 个项目的门禁期望值，而那 30 个门禁的期望值都是我手写进去的常数，改错一处就是新的假绿。要动就整批重做。

推导和重算步骤全在 `PHYSICS.md` 第七节，反解脚本是 `_tools/solve-thrust.mjs`，随时能重跑。

**发布时注意：不要在一条视频里同时出现「1.230 s」和「1.188 s」。**

## 共用模块

改这两个文件会影响所有项目，改之前想清楚：

- `shared/reel-export.js` —— 1080×1920 与 1080×1350 导出、PNG 魔数校验、确定性随机
- `shared/design-tokens.css` —— 颜色、字号、8px 网格、圆角 0

各项目的 `build.mjs` 每次都会从 `shared/` 覆盖进项目。**要改就改 shared 那份**，改项目里的会被冲掉。

## 新建一个项目

```bash
node _tools/newproj.mjs <项目名> [three|canvas2d|svg|static]
cd projects/<项目名> && cmd /c "npm i"
```

生成完整的构建、四道测试、README 骨架。之后只要写 `src/main.js` 和 README。

## 设计上的几条硬规矩

这些不是审美偏好，是踩过坑的结论：

- **圆角一律 0。** 圆角卡片 + 紫蓝渐变 + Inter 字体，是「AI 生成」最明显的三个标记。
- **数字一律等宽。** 比例字体的数字在小尺寸下会抖。
- **只用一种强调色。** 橙色 `#E8590C`。多色等于没有重点。
- **不留死区。** 画面填满，空白必须是量出来的，不是懒得排。
- **禁词表**：赋能 / 助力 / 打造 / 一站式 / 全方位 / 多维度 / 综上所述 / 由此可见 / 让我们一起 / 你是否 / Dive into / Unlock / Welcome to / Whether you're
