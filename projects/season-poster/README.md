# season-poster —— 赛季成绩单

把整个赛季 8 站的最好成绩、名次、以及同期改过的三件事，压成一张竖版长图。

起因是赛季总结会。我们做了 40 页 PPT，讲到第 12 页就没人听了。
回去就把它砍成一张图：**一条成绩曲线，一句话结论，一个能扫二维码的口径说明。**
发出去的效果比 PPT 好——因为它只有一屏，读不完也就那么点东西。

## 怎么跑

双击 `index.html`。不用服务器，不用联网。

两个开关：趋势线、逐点数值。点「导出」出 1080×1920 竖版 + 1080×1350 封面。

## 里面有什么

数据是一个数组，`src/main.js` 第 17 行：

```js
const SEASON = {
  team: '长风 CZ-3',
  label: '2025 赛季',
  track: 20.0,
  events: [ /* 8 站 */ ],
};
```

每站六个字段：`d` 日期、`name` 站名、`t` 用时、`rank` 名次、`field` 参赛队数、
以及三个工程量 `mass` / `cg` / `align`。

| 站 | 用时 | 名次/队数 | 质量 | 质心高 | 直线度 |
|---|---|---|---|---|---|
| 校内试跑 | 1.284 | 14/24 | 58.4 | 24.8 | 0.40 |
| 区预选 | 1.271 | 11/24 | 58.2 | 24.6 | 0.38 |
| 区决赛 | 1.243 | 8/24 | 57.9 | 24.1 | 0.33 |
| 市预选 | 1.228 | 6/32 | 57.6 | 23.8 | 0.31 |
| 市决赛 | 1.196 | 4/32 | 57.1 | 23.2 | 0.26 |
| 省预选 | 1.152 | 3/40 | 56.4 | 22.6 | 0.22 |
| 省决赛 | 1.121 | 2/40 | 55.2 | 21.9 | 0.15 |
| 全国总决赛 | 1.096 | 1/48 | 54.1 | 21.4 | 0.10 |

衍生量：最好 1.096，最差 1.284，降幅 **−0.188 s = −14.6%**。

## 怎么做的

**版面分四段**：标题 → 两个大数（最好成绩 / 降幅）→ 逐站曲线 → 逐站表 + 口径。

**曲线不是普通折线。** 横轴是站次，纵轴是用时，但**名次和参赛队数共用同一个框**，
所以名次走右侧副轴。两个不同量纲塞一个框里本身是有争议的画法，
但赛季总结只关心「一路往上」，这样读最快——**这个取舍写在口径里了**。

**趋势线**是最小二乘直线，只用来看斜率的正负，不当预测：

```
slope = Σ(x−x̄)(y−ȳ) / Σ(x−x̄)²
```

`fit.b` 直接在 `getState()` 里暴露出来，方便外面核对。

**平均速度那行是特意加的**：「平均速度 = 20 m ÷ 用时，把加速段和末段一起抹平了。」
因为每次有人看到 1.096 s 都会问「那末速多少」，而平均速度和末速差得很远
（20 / 1.096 = 18.2 m/s 的平均，末速要高得多）。与其被问，不如先写上去。

**同时改的三件事**单独占一段：质量、质心高、直线度。三条都往下走。

## 怎么验证没坏

```bash
cd projects/season-poster
node build.mjs
node tests/gate.mjs
node tests/visual.mjs
node tests/layout.mjs
node tests/fonts.mjs
node tests/ascii.mjs
```

`gate.mjs` 这一轮换掉了。原来 32 行，只验 PNG 大于 4 KB——那只证明有东西被导出，
不证明画面上有内容。现在多验四类：墨量 / 色数 / 最长连续空带 / 确定性 / 参数漂移。

参数漂移这条在**这个项目里只能测两个**，因为它的可调参数只有两个布尔开关
（`fitLine`、`values`）。所以输出是 `参数漂移 2/2 变`——两个开关都能让画面变，
说明渲染确实在读状态，不是画死的。

当前输出：

```
GATE OK  |  画布 1080×1920  主图 261KB  封面 214KB  墨量 22.95%  160 色  最长空带 50px  参数漂移 2/2 变  外网请求 0
```

## 已知问题

1. **这 8 站数据是编的。** 为了让曲线好看，用时做成严格单调下降
   （1.284 → 1.096）、名次做成严格单调上升（14 → 1）。
   真实的赛季不会这么顺——中间一定有反复。**发出去之前必须换成真实成绩，
   否则这是在编数据。**

2. **−14.6% 的降幅只用了两个点。** `pct = (末站 − 首站) / 首站`，
   中间 6 站完全不影响这个数。如果首站那天下雨跑崩了，这个百分比就虚高。

3. **「同时改的三件事」是相关性，不是因果。** 质量、质心高、直线度三条一起降，
   和成绩提升叠在一起，但这三条本身也互相纠缠（减重会抬高质心，
   质心降下来又会改变轮荷分配）。一张图讲不清哪个起了作用，
   图上也没做任何分离——**这是最容易被人挑的地方**。

4. **名次和用时共用一框，副轴没有刻度标注。** 右侧只写了「名次/参赛队数」，
   没画刻线，读者没法读出具体名次，只能看趋势。

5. **封面会把下半张图切掉。** 1920 → 1350 只保留上面 70%，
   逐站表（y≈1718）和数据来源那行（y≈1796）都在 1350 以下，**封面上看不到**。
   也就是说封面只有曲线没有表——这个是有意的（封面要第一眼），但要知道。

6. **趋势线是普通最小二乘，没给置信区间。** 8 个点拟合一条直线，
   `slope` 报出来只有正负，没有误差范围。严格讲这不该叫「趋势」该叫「斜率」。

7. **赛季末质心 21.4 和 `spec-sheet` 的默认 `cg: 21.4` 是同一个数**，
   但一个是赛季末实测、一个是图纸默认值，同源不同义。两个项目同时发出去会被问。

8. **`tests/gate.mjs` 之前只验 4 KB**，和 `spec-sheet`、`pit-display` 一样，
   都是同一个模板生成的。这一轮三个一起换了。
