# team-directory —— 队员名录

> 在线版：https://zhuka4141-cmyk.github.io/stem-racing/projects/team-directory/
把队里的人排成一张 1080×1920 的名录卡，能按角色筛、按关键词搜，导竖版和封面两张。

数据写死在 `src/team.js` 里，是一个普通 JS 常量。页面不读外部文件、不联网、不存任何东西。

---

## 怎么跑

```
node build.mjs
node tests/gate.mjs
node tests/visual.mjs
node tests/fonts.mjs
node tests/ascii.mjs
node tests/shot.mjs
```

`shot.mjs` 会把画布原样存成 `qa/card.png`（1080×1920）和 `qa/card-cover.png`（1080×1350）。

改名册：编辑 `src/team.js`，然后重新 `node build.mjs`。

---

## 卡片长什么样

一张计时表式的名单，不是卡片墙。

- 顶上 0–240 是 IG 状态栏死区，只放一条细线和 5.5% 透明度的 `ROSTER` 水印
- 240 起是橙色短杠 + `STEM RACING` + 66px 的「队员名录」，右上角是 68px 的在册人数
- 412–486 是三列抬头：赛季 / 筛选 / 显示
- 496 开始是名单。每一行：左侧 3px 竖条（队长是橙色，其余 20% 白）、序号、25px 姓名、右下角色、第二行一句话和入队日期
- 隔行底纹 `rgba(242,240,235,0.07)`，读起来就是一张表
- 1232 起是底部数据条：显示 / 在册 / 最早入队，下面一行是角色分布
- 1394 起是页脚

行高是跟着人数走的：`rowLayout(n)` 在 92px 和 56px 之间取，10 个人的时候是 73px 一行。

## 搜不到人的时候

这是这个项目唯一容易糊弄过去的地方。筛选条件命中 0 人时，如果直接 `return`，导出的就是一张纯黑卡片——字节数照样过 4096，PNG 魔数照样对，门禁如果不量画面就抓不到。

所以 `drawEmpty()` 不是清空，而是**照样画满整张表**：同样数量的行、同样的隔行底纹、同样的序号，行里放 `- - -` 和 `--`，中间压一块底色打断底纹，写上「没有匹配的队员 / 筛选「x」· 搜索「y」· 在册 10 人 / 清掉筛选和搜索词就回来」。

门禁直接量这一屏的墨量，要求 ≥ 8%。实测 27.12%。如果哪天有人把 `drawEmpty()` 改成 `return`，这条会立刻挂。

---

## 门禁在查什么

| # | 断言 |
|---|---|
| 1 | `dist/app.js` 里没有 `fetch(` / `new XMLHttpRequest` / `sendBeacon(` / `localStorage.set` / `sessionStorage.set` / `indexedDB.open` / `document.cookie=` |
| 2 | 运行时把上面这些 API 全包一层计数器，全程必须都是 0 次 |
| 3 | 默认 10 人，全部显示，`selfTest()` 通过，画布 1080×1920 |
| 4 | 五个角色分别筛，人数加起来必须等于在册数；机械组里不能出现队长 |
| 5 | 搜「林」出林知远；搜「电控」出 2 人；搜一句话里的「气瓶」也能出人 |
| 6 | 搜不存在的东西 → 0 人，且卡面墨量 ≥ 8% |
| 7 | 重置回 10 人 |
| 8 | 导出两张，字节数 > 4096，前 8 字节是 PNG 魔数 |
| 9 | 页面里没有外站 `src` / `href` |
| 10 | 刷新之后回到默认状态，搜索框清空 |
| 11 | 全程请求全是 `file://` / `data:` / `blob:` |

第 4 条用的是「加起来必须等于 10」而不是「机械等于 3」，因为前者同时能抓住漏人和多人的情况。写死 3 只是顺便。

## 实测

| 项 | 值 |
|---|---|
| `dist/app.js` | 15 KB |
| 竖版 1080×1920 | 166 KB |
| 封面 1080×1350 | 136 KB |
| 安全区整体墨量 | 33.49% |
| 安全区 150px 连续死区 | 0 处 |
| 空结果状态墨量 | 27.12% |
| 页面用到的不同字符 | 203 个 |
| MONO / DISP 各查 | 201 字，缺 0 |
| 门禁静态规则 | 7 条，0 命中 |
| 全程网络请求 | 8 条，全部本地协议 |

字符数 203，比项目一多，因为人名和一句话里的字都算进去了。字体栈末尾挂 `Microsoft YaHei` / `Noto Sans SC` 兜中文——`Consolas` 和 `Barlow Condensed` 都没有中文字形，不挂就是满屏豆腐块。

豆腐检测不是查黑名单：每个字渲染成位图，和一个私用区码位（一定没字形）比 FNV 哈希，一样就是缺字。

## 已知缺陷

1. **13 个人以上放不下。** 行高最低压到 56px，`ROW_AREA / ROW_MIN_H = 13`，第 14 个人开始不画。页脚会写「还有 N 人没上卡」并变成橙色，但那些人确实不在卡上。

2. **改数据要改代码。** `src/team.js` 是个常量文件，加一个人得开编辑器改数组再 `node build.mjs`。没做编辑界面，因为一旦做了就得考虑存储，而存储是这个项目明确不要的东西。

3. **搜索是朴素 `includes`。** 不分词、不支持拼音、不忽略顺序。搜「陈理」搜不到「陈以理」，搜「chen」也搜不到。要改得引拼音表，那就不再是纯静态零依赖了。

4. **角色只能单选。** 想看「机械 + 电控」两组人，只能先看一组再看另一组。多选芯片好做，但卡面上的「筛选」那一格就没法用一个词组显示了。

5. **一句话截到 22 个字。** `cut(m.line, 22)` 超过就加省略号，不换行。第二行的高度是固定的，换行会把整张表顶乱。所以长句子会丢信息。

6. **示例名单用的是像真人的中文名。** 陈以理、周牧野这些是我编的，但看起来像真人。直接发出去容易被当成真的队员名单，得先换成自己队的。

7. **4:5 封面会切掉眉标。** 封面是居中裁切，取源图 y 285–1635，y=240 的橙色短杠和 y=276 的 `STEM RACING` 不在封面里。标题和名单都在。

8. **导出永远跟着当前筛选走。** 筛到 3 个人的时候点导出，出的就是 3 个人的卡，界面上不会有任何提醒。想导全员得先点回「全部」。这是有意的行为，但很容易误操作。
