# mass-budget · 65 克的每一分钱花在哪

一台 CO₂ 车总重 65 克左右，重心横向偏 1.32 mm 就判不合格。这个页面把 65 克
拆成五件，再让你拖配重——质量和位置随便调，横向重心 y_cg 实时算出来，
**超了 1.32 mm 判定条整条变橙，字直接说「超限」。不会静悄悄地画成正常。**

配重是我们唯一还能改的东西，所以整个交互只围绕这一件。

---

## 一、车被拆成五件

| 部件 | 质量 | 横向 y / mm | 高度 z / mm | 来源 |
| --- | --- | --- | --- | --- |
| 车体（MDF 削的） | 18.0 g | +0.15 | 10.0 | `[TYPICAL]` |
| 车轮 ×4 | 9.5 g | 0 | 11.0 | `[TYPICAL]` |
| 轮轴 | 4.2 g | 0 | 11.0 | `[TYPICAL]` |
| 机构（轴承座 + 气瓶夹） | 19.3 g | −0.40 | 14.0 | `[VERIFY]` |
| 配重 | 14.0 g | +4.0 | 8.0 | 可调 |
| **合计** | **65.0 g** | | | |

z 的零点定在赛道面，y 的零点定在车体中心线。y 正方向是副驾驶侧。

## 二、重心怎么算

就是加权平均，没有别的：

```
y_cg = Σ(m_i · y_i) / Σ m_i
     = (18.0×0.15 + 9.5×0 + 4.2×0 + 19.3×(−0.40) + 14.0×4.0) / 65.0
     = (2.70 + 0 − 0 − 7.72 + 56.00) / 65.0
     = 50.98 / 65.0
     = 0.784 mm
```

`0.784 / 1.32 = 59%`。初始状态已经用掉了快六成的横向余量，这个数比队员
想象的高——他们一直以为「配重放中间就没事」。

质量占比：

```
车体   18.0/65 = 27.7%
车轮    9.5/65 = 14.6%
轮轴    4.2/65 =  6.5%
机构   19.3/65 = 29.7%   ← 最重的一件，而且不在中线上
配重   14.0/65 = 21.5%
                 ─────
                 100.0%
```

机构（19.3 g，29.7%）比车体还重一点，而且整体偏 −0.40 mm。这是队里第一次
把账算清楚之后最意外的一条。

## 三、1.32 mm 这条线

临界横向偏移 1.32 mm 是车队实测出来的，不是算出来的——跑偏到某个程度
导轨就拉不住了。我按严格大于处理：

```js
const over = Math.abs(ycg) > LIMIT;   // 正好 1.32 不算超
```

配重位置拖到多少会超：

```
y_b = +6.487 mm   →  y_cg = +1.320 mm   刚刚不超
y_b = +6.600 mm   →  y_cg = +1.344 mm   超 0.024 mm
y_b = −5.770 mm   →  y_cg = −1.320 mm   刚刚不超
```

两边不对称，因为机构本身偏 −0.40 mm 把中线往左拽了。往右能走 6.49 mm，
往左只能走 5.77 mm。

拖到滑块两端：

```
y_b = +8.0 → y_cg = +1.646 mm   超 0.326 mm
y_b = −8.0 → y_cg = −1.800 mm   超 0.480 mm
```

**两边都会被报警**，负方向也一样。这是刻意的：跑偏不分左右。

## 四、偏航力矩和左右轮载荷

横向偏心意味着推力不通过重心，车会被推着转：

```
M_yaw = F_peak · y_cg
      = 21 N × 1.32e-3 m
      = 0.0277 N·m
      = 27.7 mN·m
```

这个数看着小，但车只有 65 g，转动惯量更小。

左右轮载荷用最简单的双弹簧近似：

```
ΔN / N = 2 · y_cg / track = 2 × 1.32 / 42 = 6.29%
```

在临界点上，一边轮子比另一边多扛 6.29% 的重量。轮距 42 mm 也是 `[VERIFY]`，
我没实测过。

## 五、重心高度我没有设阈值

`z_cg` 会随配重高度变：

```
z_b =  2 mm → z_cg = 9.675 mm
z_b =  8 mm → z_cg = 10.968 mm
z_b = 16 mm → z_cg = 12.691 mm
```

轮轴平面在 11.0 mm。很多人会顺口说「重心不能高过轮轴」，但我**没有**为
z 设一个报警阈值——因为我没有依据。1.32 mm 那条线是实测的，z 这条线不是。
凭空造一个数字然后画条红线，比不画更糟。

所以 z 只显示数值和相对轮轴平面的位置，不判合格与否。

## 六、报警是画出来的，不只是变量变了

`tests/gate.mjs` 里有一条专门量像素：

```js
window.__app.setBallast({ y: 4 });   const safe = sample();   // 判定条 y=1396 那一行
window.__app.setBallast({ y: 8 });   const over = sample();
// 断言 over.r - safe.r > 60
```

实测 `R 36 → 218`，差 182。光改变量不重绘的话这条过不去。

其它断言：

- 五个质量占比合计 = 100%（±1e-6）
- 各件质量之和 = 总质量（±1e-9）
- 五个部件的贡献之和 = y_cg（±1e-9）——即重心不是硬编码的
- 配重拆掉后 y_cg = −0.0984 mm（手算：(2.70 − 7.72)/51.0，注意总重变成 51 g 不是 65 g）
- 左右轮载荷合计 = 100%（±1e-9）
- 重心高度落在部件高度区间内
- 初始配重下不报警（0.784 / 1.32 mm）
- 配重右移时 y_cg 严格单调增（1.22 → 1.32 → 1.43 → 1.65）
- 至少一个位置真的越界并报警
- 越界时判定条整条变强调色（R 36 → 218，Δ182）
- 越界时余量为负（−0.326 mm）
- 越界时 |M_yaw| > 25 mN·m（34.56）
- 配重左移同样越界并报警（−1.800 mm）

最后一次跑：

```
数值断言：13 条全 ✓
GATE OK  |  竖版 150KB  封面 135KB  |  墨量 11.49%  98 色
```

墨量只算**默认配重、不报警**那一帧，因为它才是用户打开时看到的画面。
QA 截图另外切到越界态拍，专门留报警长相的证据。

## 七、我知道的问题

1. **每个质量都是厨房秤称的，误差 ±0.5 g。** 五件加起来误差最坏 ±2.5 g，
   是总重的 3.8%。换算到 y_cg 大约 ±0.05 mm——对比 1.32 mm 的阈值是 4%。
   也就是说这个模型的可信度卡在秤上，不在公式上。

2. **1.32 mm 这个数我不知道是怎么来的。** 队里只留了个数字，没有实验记录。
   它可能是「导轨能拉住的最大偏移」，也可能是「某次跑偏 3 次里 2 次失败」的
   经验值。我按前者用，但没验证过。

3. **左右轮载荷用的是刚性双弹簧。** 真实的 MDF 车体和 3D 打印轮架都有柔性，
   载荷不会像公式那样线性分。这条只在趋势上有意义。

4. **没算转动惯量。** 要判「会不会翻」需要 I_xx，我只给了 y_cg 和 z_cg 两个
   一阶矩。严格说 y_cg 超 1.32 mm 到底是因为侧翻还是因为跑偏，这个模型分不清。

5. **饼图和柱状图共用一份数据，但 6.5% 的轮轴在饼图上只有 23°。** 标签环
   在最小那一片上会压到相邻标签，我把标签统一放到右侧引线上了，仍然局促。

6. **导出的是当前状态，不是报警状态。** 用户如果没拖到越界，导出的图上就没有
   橙色的报警条。这算设计选择，但对「给人看这个工具能报警」来说是个损失。

7. **机构 19.3 g 的读数最不可靠。** 它由三种材料拼的，秤上去的时候还带着
   两个 M3 螺栓。这一件的 ±0.5 g 直接进 y_cg。
