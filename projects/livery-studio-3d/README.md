# 涂装工作室 · Livery Studio

> 在线版：https://zhuka4141-cmyk.github.io/stem-racing/projects/livery-studio-3d/
同一台三维车体，八套涂装，实时换材质。

做这个是因为车队每次讨论涂装全靠嘴说——「那个深蓝一点的红」「比刚才那个亮」——谁也说不清。换成能点、能截图的八套之后再吵，至少大家看的是同一张图。

---

## 怎么跑

双击 `index.html`。改代码后：

```
node build.mjs
```

`file://` 下 ES module 被 CORS 拦，所以 esbuild 打 IIFE。

## 门禁

```
node tests/gate.mjs
```

```
GATE OK  |  竖版 305KB  封面 275KB  |  墨量 54.85%  141 色  |  8 套预设
```

关键的五条：

1. **预设 ≥6 套**（实际 8 套）
2. **每套都能选中**，id 和名字都不许重复
3. **每套画面都不同** —— 八次切换导出八个不同哈希，`8/8`
4. **切换后导出字节必须变** —— `ffdbe9cb → b29b86f8`
5. **结论行整体落在封面 1350 以内** —— 墨迹 1319..1345。门禁读的是 `window.__app.getBands()`，量的是刚画出去的那一行，不是另抄一个数

第 3、4 条是这个项目的命门。这个目录最初是 2660 字节的空壳，`dist/app.js` 1186KB 里躺着完整的 three.js，gate 报 `GATE OK | 67KB | 13.38% | 60 色` —— 数字全对，画面是同一张空壳图。**空壳能导出合法 PNG，也能让 `selfTest()` 返回 true，唯独换不了色。** 所以防假绿只能靠比哈希，不能靠比字节数。

## 一条配色规则，我改过一次

`selfTest()` 第 7 条会拦「AI 默认配色」。第一版写的是：

```js
if (b > r + 40 && b > g + 40) errs.push('偏紫蓝');
```

这一版把两个正经颜色判掉了：

- **竞赛蓝 `#1B3A6B`** —— hue 216.7°，深海军蓝，赛车里最常见的颜色之一
- **素碳 `#1A1A1F`**、**夜巡黑 `#111114`** —— hue 240°，但饱和度只有 0.09，本质是灰不是紫

按蓝通道比大小，海军蓝和近黑跟紫罗兰长得一模一样。要分开只能算色相和饱和度：

```js
if (h >= 235 && h <= 300 && s >= 0.30) errs.push('落在靛蓝/紫罗兰带');
```

- 靛蓝 `#4F46E5` → hue 242, sat 0.76 → **拦下**
- 紫罗兰 `#8B5CF6` → hue 258, sat 0.90 → **拦下**
- 海军蓝 `#1B3A6B` → hue 217 → **放行**
- 近黑 `#1A1A1F` → hue 240, sat 0.09 → **放行**

要拦的其实是 `indigo-500` / `violet-500` 那一段——AI 生成界面最爱用的默认色。判断该落在色相上，不该落在通道大小上。

## 已知问题

**1. 颜色改不了质量，但真车改得了。**
界面上一句「颜色只影响外观，不改质量与气动」，这句话在软件里成立，在真车上不成立。一套面漆 3–6 g，整车 65 g，占 5–9%。`shared/racing-core.js` 里质量是 `[VERIFY]` 的 0.065 kg，换涂装应该重算 `m`，进而改加速度、改成绩。这里完全没联动。

**2. 4:5 封面是居中裁切，上下各切 285 px。**
`reel-export.js` 的 `resample()` 走 cover 算法：`scale = max(1080/1080, 1350/1920) = 1`，`dy = (1350 − 1920) / 2 = −285`，所以封面保留的源行是 **285..1635**，上下各切 285 px。

这里原先记着「说明行画在 y=1418，封面看不见，所以没改」。量过之后这句是错的：1418 映射到封面 y 1133，一直在画面里。真正被切掉的是页眉那条 3 px 强调条——原来在 y 282..284，整条落在 285 以上，已经挪到 296。

结论行现在按 1350 卡死：`SPEC.noteBase = 1340`，墨迹 1319..1345，说明行跟着挪到 1376。这比实际可见窗口 1635 保守 285 px，以后谁把裁切改成上对齐也不会把结论切掉。门禁第 5 条守它——把 `noteBase` 改回 1382，立刻红 `y 1361..1387 > 1350`。

**3.「编号条」其实没有编号。**
`stripe: 'numeral'` 只是画了一条白色纵条，上面一个数字都没有。要做真编号得加 CanvasTexture 或用 `TextGeometry`，前者要处理 2 的幂次纹理，后者要额外字体文件——都没做。

**4. 条纹是浮在车身上的平板。**
四条 `BoxGeometry` 厚度 0.0009 m，直接摆在车身顶面 y = 0.0302。车头削了一刀（`nose` 是独立网格），但条纹是整条 `L*0.96` 的板子，**不跟着车头收窄**，从侧面看会看到条纹比车头宽出一截。

**5. 八套预设全是手挑的，不能调。**
没有取色器、没有自定义。想加第九套得改代码。

**6. 银灰和素碳肉眼难分。**
`metalness` 0.85 vs 0.28 在只有一个顶部灯板的情况下差别很小。要拉开差距得加环境贴图（HDRI），那又多几百 KB。

**7. 车身全是方块，没有曲面。**
`BoxGeometry` 拼的车。真实车身是负压成型的曲面。这个精度只够看涂装分区，看不出造型。

**8. 场景雾把远处网格吃掉了。**
`Fog(0x0b0b0c, 0.45, 1.20)`，网格尺寸 1.0 m，边缘那一圈基本融进背景，判断不了车有多大。

**9. 切换是瞬时的，没有过渡。**
点「下一套」材质立刻变。真实换漆是几天的工序。没做过渡是因为导出必须确定性——中间帧会让哈希不稳定。

**10. `ctx.letterSpacing` 只有 Chromium 认。**
Firefox / Safari 忽略，字距会变。只在 Chromium 里验过。

**11. 移动端 `<select>` 会弹原生选择器。**
样式不可控，跟旁边的手写风格按钮对不上。

## 文件

```
livery-studio-3d/
├─ index.html          下拉 + 上一套/下一套 + 画布
├─ build.mjs           esbuild 打 IIFE
├─ src/main.js         八套预设 + 三维车体 + 二维叠加
├─ src/reel-export.js  导出工具（构建时从 ../../shared 覆盖）
├─ design-tokens.css   配色（同上）
└─ tests/gate.mjs      门禁
```

`src/reel-export.js` 和 `design-tokens.css` 每次构建都会被 `../../shared/` 覆盖，**要改就改 shared 那份**。

车体尺寸和 `wheel-contact-3d` 一致（长 0.200 m、轴距 0.130 m、轮半径 0.011 m），两套图可以并排放。
