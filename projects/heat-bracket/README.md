# 淘汰赛对阵图 · Heat Bracket

20 米直线、单败淘汰的赛果图。16 台车打四轮，一张 1080×1920 的竖版图能把整条晋级路线看完。

做这个东西是因为我们以前赛后发对阵图靠手画 PPT，改一个成绩就要挪半天框。现在改成生成式：数据一换，图自己重排。

---

## 怎么跑

双击 `index.html` 就行，不需要服务器。

改代码之后要重新构建：

```
node build.mjs
```

因为 `file://` 下 ES module 会被 CORS 拦死，所以用 esbuild 打成 IIFE。

## 赛制怎么算的

车数可以选 4 / 8 / 16，轮数是 `log2(n)`：

| 车数 | 轮数 | 场次 | 轮次名 |
|---|---|---|---|
| 4 | 2 | 3 | 半决赛 → 决赛 |
| 8 | 3 | 7 | 1/4 决赛 → 半决赛 → 决赛 |
| 16 | 4 | 15 | 1/8 决赛 → 1/4 决赛 → 半决赛 → 决赛 |

每场取成绩小的那台晋级，差值 `gap = t_败者 − t_胜者`。

`selfTest()` 会自己验四条：

- 轮数等于 `log2(n)`
- 总场次等于 `n − 1`（单败淘汰的必然结果）
- 每场胜者成绩确实小于败者
- 决赛只有一场

这四条只要有一条不成立就红。

## 数据是假的，说清楚

车号、姓名、成绩全都是 `mulberry32` 固定种子生成的：

```js
time = 1.150 + rnd() * 0.220   // 1.150 – 1.370 s
```

种子 `20260314 + n`，所以同一车数每次打开都是同一张图，导出可复现。

**这些数字不对应任何真实赛事。** 要换成你们队的，改 `src/main.js` 里的 `NAMES` 和 `makeField()`。

## 已知问题

按严重程度排，都是我知道但这次没解决的。

**1. 对阵图只记胜者，败者的名字根本不出现。**
每场只画赢的那台车，输家只在右下角留一个灰色成绩数字。所以这张图答不了「他赢的是谁」。真正的对阵图应该一场两个格子。为了在 880px 高度里塞下 8 场才这么压的。

**2. 4:5 封面会把下面几轮切掉。**
封面是 1080×1350，从画布顶部裁。对阵图纵向占 520–1400，所以 16 台车的时候，第一轮最下面那两场会掉出封面。发布前必须自己看一眼封面。

**3. 成绩相同不分胜负。**
判定写的是 `a.time <= b.time ? a : b`，平局直接把胜利判给排在前面的那台。真实赛事要么重赛要么比第二好成绩，这里都没有。

**4. 「与胜者差值」模式下败者那一栏没有标签。**
赢家显示 `—`，右下角显示 `+0.023`。这个 `+0.023` 没写单位也没写是谁的，第一次看的人会懵。

**5. 车名字数没有约束。**
格子宽 150px，名字从 `x+62` 开始画，右边留给成绩。四个字的车名会压到成绩上。现在 16 个名字都是两个字，属于恰好没事，不是设计上防住了。

**6. `letterSpacing` 只有 Chromium 认。**
Firefox 和 Safari 会直接忽略，字距会比这里松或者紧。我只在 Chromium 里看过，另外两个浏览器没实测。

**7. 没有平局重赛、没有季军赛、没有分组。**
现在只能是 `n` 是 2 的幂的纯单败淘汰。3 台车、5 台车这种数量跑不了。

**8. 换个种子整张图全变。**
因为成绩和名次都是种子推出来的，种子一换，谁夺冠也变了。这不是 bug，但意味着这张图不能当「历史记录」用——它每次都是一次重算，不是一个存档。

## 文件结构

```
heat-bracket/
├─ index.html              控件面板 + 画布
├─ build.mjs               esbuild 打包
├─ src/main.js             全部逻辑：生成数据、跑淘汰赛、画图
├─ src/reel-export.js      导出工具（每次构建从 ../../shared 覆盖）
├─ design-tokens.css       配色与字号（同上）
└─ tests/                  四道检查
```

`src/reel-export.js` 和 `design-tokens.css` 是构建时从 `_stemlab/shared/` 拷过来的，**要改就改 shared 那份**，不然下次构建会被盖回去。
