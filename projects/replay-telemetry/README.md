# replay-telemetry · 一趟跑的逐帧回放

我们把车跑完 20 m 的那 1.19 秒拆成 285 帧，每一帧都留着位置、速度、加速度，
还有推力、气动阻力、滚动阻力这三个力的分量。拖时间轴到任何一帧，上面三个图
的竖直游标跟着走，下面四个力条当场重算。

做这个是因为队里一直有人在问「车到哪儿最快」。答案是**到 9.2% 的行程就最快了**，
剩下 90% 都在掉速。这个结论光看终点成绩是看不出来的。

纯 Canvas2D 手画，没有图表库。

## 一、车里到底有哪些数

| 量 | 值 | 来源 |
| --- | --- | --- |
| 整车质量 m | 0.065 kg | `[VERIFY]` 厨房秤粗称，±0.5 g |
| 等效惯性质量 | 79.88 g | 推算，见下 |
| 迎风面积 A | 1.6×10⁻³ m² | `[TYPICAL]` |
| 阻力系数 Cd0 | 0.34 | `[TYPICAL]` 圆头短舱体 |
| 滚动阻力系数 Crr | 0.008 | `[TYPICAL]` 硬塑料轮 × MDF 赛道 |
| 推力峰值 F_peak | 21 N | `[VERIFY]` 从实测加速段反推 |
| 推力时长 t_burn | 110 ms | `[VERIFY]` 同上 |
| 空气密度 ρ | 1.204 kg/m³ | `[FIXED]` 20 ℃ 标准大气 |
| 运动黏度 ν | 1.516×10⁻⁵ m²/s | `[FIXED]` 同上 |

四个轮子要跟着转，得额外推一份质量：

```
m_eff = m + Σ I_w / r_w²
      = 0.065 + 4 × 4.5e-7 / 0.011²
      = 0.065 + 0.01488
      = 0.07988 kg   →  79.88 g
```

也就是说**轮子让车重了 15 g**，占整车质量的 23%。这个数不写进去，加速度会算高 23%。

## 二、每一帧在算什么

```
m_eff · a(t) = F_thrust(t) − ½ρ·Cd0·A·v² − Crr·m·g

F_thrust(t) = F_peak · sin(πt/t_burn)   0 ≤ t < t_burn
            = 0                          t ≥ t_burn
```

半正弦推力是我选的形状，理由是气瓶出气前段猛、后段软，正弦比矩形更接近实测
加速度曲线。它只在推力段内有效，过冲完就只剩阻力。

积分用定步长欧拉，记录频率 240 Hz，每帧内部再切 50 个子步：

```js
const FRAME_HZ = 240, SUBSTEPS = 50;
const DT = 1 / (FRAME_HZ * SUBSTEPS);   // 8.33e-5 s
```

跑完的结果：

```
完赛时间      1.1885 s
终点位置      20.0009 m        ← 过了 20 m 才停，多走了 0.9 mm
末速          16.906 m/s
速度峰值      18.34 m/s  @  t = 0.1098 s（推力段刚结束）
峰值加速度    27 g
推力做功      13.506 J
总动能        13.506 J
账本残差      0.0126 J  (0.09%)
```

**为什么峰值在 0.1098 s 而不是别处**：推力半正弦在 t_burn 时降到 0，
而阻力随 v² 一直涨。两者相加在 t_burn 那一刻由正转负，所以速度极值必然
出现在推力段末尾。跑到这里只用了 20 m 里的 0.98 m，也就是 4.9% 的位移。

## 三、拖时间轴看什么

下面四根力条是**按当前帧归一化**的，不是全局固定刻度。原因是：

```
推力峰值   21 N
末段气动阻力 0.158 N
滚动阻力    0.0051 N
```

两万倍的跨度。固定刻度的话，推力段一结束，后面三根条全变成 1 px 以下的线，
等于没画。所以每帧各自取 `max(|F_thrust|, |F_drag|, |F_roll|, |F_net|)` 做分母，
条长读的是**这一帧里四个力谁占主导**，不是绝对值。

代价是：跨帧比较条长没有意义。这一点在图上没有明说，是我没做好。

## 四、数字检查

`tests/gate.mjs` 除了查导出字节和画面墨量，还跑 12 条数值断言：

- 位置积分终点 = 20.00 m ± 0.05
- 末速落在 15–20 m/s（racing-physics 给的 sanity 带）
- 完赛时间落在 1.0–1.25 s
- 等效惯性质量 79–81 g
- 速度峰值出现在推力段内（t < t_burn）
- 能量账本闭合，残差 / 总能量 < 1%
- 帧数 = 总时长 × 240 ± 2
- 拖到 3.5% / 9.0% / 95% 三个位置，落在三个不同的帧上
- 峰值段速度 > 起步段 + 5 m/s，峰值段 > 末段 + 0.5 m/s
- 拖动后位置读数同时变化
- 拖动定位的 t 与目标比例一致（±2 ms）
- 峰值前速度严格递增、峰值后严格递减（各查 0 处回落）

## 五、我知道的问题

1. **力条的归一化掩盖了真实量级。** 上面说的两万倍跨度是真的，但归一化之后
   看不出「气动阻力只有推力的 0.75%」。我试过加对数刻度，四条线挤在一起更难看。
   目前是个没解决的问题。

2. **时间轴前 9% 装了整个推力段。** 285 帧里推力段只占 26 帧，对应滑块 0→90 的
   行程。拖到 100 之后推力就是 0 了。想看燃烧过程得用键盘微调，鼠标拖不准。

3. **20 m 终点是撞线判定的，不是插值的。** 最后一帧 x = 20.0009 m，比 20 m 多
   0.9 mm。如果换成插值终止，完赛时间会短约 0.05 ms。这个误差比秤的误差小两个
   数量级，我就没改。

4. **没有建轮胎打滑。** 27 g 的起步加速度在真实赛道上肯定会让后轮打滑，摩擦
   系数不够。模型里轮子是纯滚动的，所以起步段加速度偏乐观。真实车可能需要
   把推力削掉 10–20%。

5. **Cd0 = 0.34 是拍脑袋的典型值。** 我们没吹过风洞，也没做过滑行衰减实验。
   这个数上下浮动 20% 的话，末速会变 ±0.15 m/s，完赛时间变 ±3 ms。

6. **气动阻力用的是定常假设。** 车在 0.11 s 内从 0 冲到 18 m/s，雷诺数从 0
   变到 2.4×10⁵，Cd0 其实会变。按定常算等于默认这一段 Cd0 是常数。

7. **导出封面是 1080×1350，不是原生比例。** `toPNG` 用 drawImage 缩放，
   竖版 1080×1920 → 1350 高度是等比缩到 759 宽再居中，左右会留白边。
   我接受这个，因为 IG 封面本来就要裁。

## 六、怎么跑

```bash
cd _stemlab/projects/replay-telemetry
npm i
node build.mjs          # esbuild 打 dist/app.js
node tests/gate.mjs     # 数值断言 + 墨量 + 导出
node tests/visual.mjs   # 死区 + 整体墨量
node tests/fonts.mjs    # 豆腐块检测
node tests/ascii.mjs    # 版面密度图
node tests/probe.mjs    # 分带墨量 + 页边距越界
```

必须用 `build.mjs` 打包成 IIFE，因为 `file://` 下浏览器不让加载 ES module。
