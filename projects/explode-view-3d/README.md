# 3D 爆炸图：200 mm 级 STEM Racing 车体

> 在线版：https://zhuka4141-cmyk.github.io/stem-racing/projects/explode-view-3d/
我把我们那台 CO₂ 拉动车的车身拆开，做成一个能拖的 3D 爆炸图，竖版 1080 × 1920，可以直接当 Reels 的素材。

场景是真的 3D（Godot 4 + Web 导出），不是画出来的假轴测图。拖一下画面，零件会沿各自的轴线散开；反着拖就装回去。滚轮也能推。

## 怎么打开

**双击 `serve.cmd`**，浏览器会自动开 http://127.0.0.1:5188/。

双击 `index.html` 是不行的，会卡在加载页。原因是 Godot 的 Web 构建要靠 `fetch()` 去下载 `index.wasm`（41.7 MB）和 `index.pck`，而 `file://` 协议下浏览器按同源策略直接拒绝这类请求，控制台会报 CORS。这不是我写错了，任何 Godot / Unity / Emscripten 的 Web 构建都这样，必须有 http。

所以要么用 `serve.cmd`，要么自己开一个静态服务器：

```
node tools/serve.mjs
```

如果你确实用 `file://` 打开了，页面会显示一块橙色提示，告诉你该怎么办，不会白屏。

## 图里的东西

七条标注，编号和下方列表一一对应：

| # | 零件 | 尺寸 | 质量 |
|---|---|---|---|
| 01 | 车身 | 200 × 38 × 44 mm | 33.11 g |
| 02 | CO₂ 导管 | Ø19.6 × 62，壁 0.6 mm | 3.55 g |
| 03 | 尾翼 | 展 60 × 弦 22 × 厚 3 mm | 3.58 g |
| 04 | 前轮 ×2 | Ø28 × 9 mm | 3.06 g |
| 05 | 后轮 ×2 | Ø34 × 12 mm | 4.76 g |
| 06 | 前轴 | Ø3 × 42 mm | 2.33 g |
| 07 | 后轴 | Ø3 × 66 mm | 3.66 g |

合计 54.05 g，轴距 130 mm。

**这些数字不是编的，也不是网上抄的。** 车身是 8 个截面站位放样出来的实心壳，程序里直接量它的包围盒；每个零件的质量 = 几何体积 × 密度，在 `godot/scripts/catalog.gd` 里当场算，界面只是把算出来的数打出来。所以只要改尺寸，质量会跟着变，不会对不上。

反过来说，这也意味着密度和填充率一旦是估的，质量就是估的。见下面的已知问题。

## 导出

右下角 `导出 PNG`，会把当前 1080 × 1920 的画面存成一张 PNG 下载下来。导出时会临时把按钮自己藏掉，所以图里不会有按钮。

渲染视口用的是 `stretch/mode = viewport`，根视口恒等于 1080 × 1920，跟浏览器窗口多大没关系。所以导出的图不管你屏幕是什么比例，都是 1080 × 1920。

## 目录

```

serve.cmd             一键起服务
godot/                场景与脚本
  scripts/catalog.gd  所有尺寸、密度、质量计算
  scripts/car.gd      按 catalog 的数值建 3D 网格
  scripts/hud.gd      排版：标题、标注、表格
  scripts/main.gd     相机、灯光、爆炸插值、导出状态机
web-src/              注入用的 HTML 头和 app.js 源码
tools/build.mjs       构建：子集字体 → 导入 → 导出 → 注入
tools/subset_fonts.py 把 17.7 MB 的思源黑体裁到只剩用到的字
tools/serve.mjs       无依赖静态服务器
tests/gate.mjs        验收门禁
tests/ascii.mjs       PNG 转字符密度图（这台机器没有看图能力时用）
qa/                   门禁产出的截图
```

## 重新构建

```
node tools/build.mjs
```

需要 Godot 4.4.1 在 `../../_tools/godot/`。改了任何中文文案之后**必须**重跑，因为字体是按用到的字子集出来的，新字不在里面就会变成豆腐块。只想改 HTML 外壳的话加 `--no-fonts` 跳过字体那步。

## 测试

```
node tests/gate.mjs
```

会检查：画布是不是 1080 × 1920、导出的字节是不是合法 PNG 且尺寸对、拖拽前后画面有没有变化、桌面 1440 × 900 下等比缩放对不对、控制台有没有 `console.error` / `pageerror`、有没有 4xx 和外部 CDN 请求。全过打 `GATE OK`，有一条不过就 exit 1。

没有看图能力的时候，用这个把 PNG 降成字符密度图看版式：

```
node tests/ascii.mjs qa/vertical-1080x1920.png 100
node tests/ascii.mjs qa/vertical-1080x1920.png 92 60,410,1020,1070
```

最后一个参数是裁剪框 `x0,y0,x1,y1`。

## 已知问题

**数值这块**

1. **车身实心率 `BODY_SOLID_RATIO = 0.60` 是我拍的。** 真车要挖电池仓和配重孔，实际比 0.6 低多少我没量。这一个数直接决定 33.11 g 准不准。
2. **四个密度是查表来的，不是买料实测的**：椴木 0.42、碳纤 1.60、钢 7.85、聚氨酯 1.15 g/cm³。钢材那个还算可信，椴木不同批次能差 ±15%。
3. **轮子的填充率 0.24 / 0.19 完全没有根据。** 我按"轮毂中间空一部分"随手填的，没有拆过轮子称过。
4. **54.05 g 从来没上过秤。** 它是上面这些估值的和，估值错多少它就错多少。别拿它去交参赛表。
5. **组委会的最低质量限制我没核对过。** 印象里是有下限的，具体多少、按整车还是按车体算，我不确定，要用的话自己去翻当年规则书。

**渲染和版式这块**

6. **桌面打开时上下会留大片黑边。** 这是故意的：画面锁死 9:16，宽屏下只能居中留白。想满屏就开 F11 或者直接用手机。
7. **没在真手机上试过。** 只在 Chromium 里模拟过 1080 × 1920 和 1440 × 900。iOS Safari 的 WebGL2 和内存限制对 41.7 MB 的 wasm 不太友好，大概率要等更久甚至加载失败，我没验证。
8. **41.7 MB 的 wasm 首次加载很慢。** 本地几秒，挂到公网按带宽算，慢的话十几秒。没有做 gzip / brotli，服务器得自己配。
9. **字体是从 Windows 自带的 `NotoSansSC-VF.ttf` 和 `consola.ttf` 子集出来的**，塞在 `godot/assets/fonts/` 里。思源黑体是 OFL，理论上可以随项目分发，但子集化之后我还没去核对许可条款和署名要求。要公开发布的话这块得补。
10. **改中文文案忘了重跑 `tools/build.mjs`，新字会变豆腐块。** 字体是静态子集，不是动态的。这个坑我自己踩过一次。

**功能这块**

11. 爆炸程度只有拖拽和滚轮两种输入，没有做键盘控制，也没有做"自动播放爆炸动画"。
12. 导出的是当前帧，不带透明背景，也不支持 2x / 3x。要更高分辨率得改 `PX_PER_MM` 和视口尺寸重新构建。
13. 三个侧面的零件（左右前轮、左右后轮）各只标了一个号，另一个是靠 `legend_only` 隐掉的，不然画面太挤。
