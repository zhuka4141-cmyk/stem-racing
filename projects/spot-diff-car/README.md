# 找不同：两台车的六个工程参数差异

两台 CO2 直线加速车的侧视图，六个工程参数不一样。点出来，每一处都告诉你
这台车和那台车的实际数值，以及这个数值在 20 m 赛道上变成了什么。

不是涂色找茬。六处差异全部是 `car.js` 画图时真正读进去的参数，`physics.js`
用同一组参数算阻力、等效质量和质心。

## 怎么玩

开 `index.html`，在车身上点。点中一处，下面那张卡换成这一处的对比：两边
的数值、差了多少、以及它带来的后果。找不到就点检查表右列，那里一直是
`— / —`，找到一行填一行。

点空白只记一次失误，不扣分，也不藏起来。

## 六处差在哪

| 参数 | CAR A | CAR B | 读者能看到的做法 |
|---|---|---|---|
| 迎角 | 4.0° | 2.0° | 车身前高后低的角度 |
| 轮径 | 30.0 mm | 26.0 mm | 轮子大小 |
| 配重位置 | 152 mm | 118 mm | 车身上那块橙色的位置 |
| 尾翼角度 | 0° | 8° | 尾翼掀没掀起来 |
| 离地间隙 | 4.0 mm | 7.5 mm | 车身离轨道的高度 |
| 鼻锥长度 | 34 mm | 28 mm | 车头尖出来的长度 |

合起来的结果：

| | CAR A | CAR B |
|---|---|---|
| Cd | 0.520 | 0.734 |
| 迎风面积 /10⁻⁴m² | 16.000 | 17.752 |
| 总质量 | 65.00 g | 65.00 g |
| 等效惯性质量 | 79.88 g | 76.18 g |
| 其中转动部分 | 14.88 g | 11.18 g |
| 质心位置 | 124.00 mm | 109.58 mm |
| 前轴荷 | 32.9% | 43.2% |
| 20 m 用时 | 1.2133 s | 1.2050 s |
| 过线速度 | 16.193 m/s | 15.682 m/s |

B 赢了 8.3 ms，但它过线更慢。原因是 B 的阻力更大（Cd 高 41%），可等效惯性
质量少 3.70 g，起步那一段的加速度补回来了，到线前已经被阻力吃掉。第一次
跑出这个结果我们还以为算错了，把 `dt` 从 5e-5 改成 5e-6 又跑了一遍，一样。

## 物理

```
(m + Σ I_w/r_w²)·a = F(t) − ½ρC_dA·v² − C_rr·m·g
```

- ρ 1.204，C_rr 0.008，A0 1.6e-3 m²，Cd0 0.34，车长 200 mm
- 推力半正弦，F_peak 21 N，t_burn 110 ms
- 轮子 I_w = 4.5e-7 kg·m²，r 11 mm，四个
- 迎角每度 +0.045 Cd，尾翼每度 +0.038 Cd
- 离地每高 1 mm，迎风面积 +1.0%；鼻锥每短 1 mm，+1.2%

滚阻用车身质量，不用等效质量。轮子的转动惯量抗拒的是角加速度，它不增加法向
载荷。这一条是唯一能对上队里台架数据 1.188 s / 16.91 m/s 的写法（那是迎角 0°、
尾翼 0° 的标定车）。换成等效质量算滚阻会得到 1.1890 s / 16.890 m/s。

## 已知问题

**1. 六处差异是按「侧视图能看见」挑的，不是按重要性挑的。** 轮距其实对
抗侧倾影响很大，侧视图完全看不出来，只能砍掉。所以这六项不等于「最关键的
六项」。

**2. 轮径改了，轮子质量也跟着变，我用配重补回来凑 65 g。** 轮子质量按
直径平方走，A 四个轮 14.88 g，B 只有 11.18 g。真实加工里配重不一定能补
到 0.1 g 这个精度，所以「两台车同组别限重」是个简化。

**3. Cd 随角度的斜率是台架拟合，不是风洞数据。** 迎角 0.045/deg、尾翼
0.038/deg 这两个数覆盖我们实际会跑的范围（迎角 0° 到 6°），出了这个范围
不敢保证。所以文案里那些百分比该当参考，别当定论。

**4. 热点的点击半径是画布上 40 px，显示出来是 40 CSS px 直径。** 手机上
按得动，但低于 44 px 的通行建议值。想改的话在 `main.js` 里改 `hotspots.push`
那个 `r: 40`，改大之后相邻两处差异会互相抢点击。

**5. 找到之后卡片只显示最后点中的那一个。** 想看回前面某处得再点一次它。
做成列表会好看，但那张卡放不下六段解释。

**6. 只有 `click`，没有处理 `pointerdown`。** 触屏上会有约 300 ms 的点击
延迟，安卓 Chrome 上能感觉到。

**7. 时间按 dt = 5e-5 的辛欧拉积分，报到 0.1 ms。** 积分误差比这个末位
小，但它不是解析解，改 `F_PEAK` 或 `T_BURN` 之后建议重跑一遍台架标定。

**8. 中文字形回退到微软雅黑。** 没打包中文字体，iOS 上会落到苹方，字宽
和雅黑不一样，检查表右列的对齐会差几个像素。
