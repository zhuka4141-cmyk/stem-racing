# 20 m 直线加速成绩预测实验室

> 在线版：https://zhuka4141-cmyk.github.io/stem-racing/projects/lap-time-lab/
双击 `index.html` 就能跑。不联网，零依赖，六个滑杆拖一下，成绩和四张图同步变。

做这个的起因很具体：区赛那台车跑出 1.15 s，赛后复盘时没人说得清这 1.15 s 是怎么来的。改一个参数，成绩会变好还是变坏，全靠手上感觉猜。所以我把方程写下来，逐毫秒积一遍，看看到底哪一个参数在管成绩。

## 怎么跑

- 双击 `index.html`，Chrome 或 Edge。不需要服务器，不加载任何外部资源。
- 交付门禁：`node tests/gate.mjs`（需要 playwright-core）
- 布局自检：`node tests/layout.mjs`
- 导出海报：点右下角「导出 1080×1920 PNG」，浏览器直接下载。

## 模型

一维纵向动力学，RK4，步长 1 ms：

```
(m + Σ I_w/r_w²)·a = F_thrust(t) − ½ρCdA·v² − Crr·m·g − F_scrub − F_bearing

F_thrust(t) = (J / (τ_d·(1 − e^(−t_cut/τ_d)))) · e^(−t/τ_d)     0 ≤ t ≤ t_cut
            = 0                                                  t > t_cut

F_bearing   = n_w·(τ_b0 + c_v·v/r_w) / r_w

F_scrub     = μ_rail · F_thrust(t) · d / L_rear
```

有两件事我一开始没意识到，后来发现绕不过去。

**推力必须逐毫秒积分，不能拿平均值乘时间。** 默认参数下峰值推力 26.06 N，而燃烧窗口（0.30 s）里的平均推力只有 J/t_cut = 4.33 N，两者差 6 倍。如果按平均值算，起步那 0.1 s 的加速度会被算小 6 倍，整条速度曲线的形状就没了。

**`Σ I_w/r_w²` 是有效质量项，不能丢。** 圆盘轮 `I_w = ½m_w r_w²`，代进括号里变成 `m_w/2`，轮半径整个抵消。默认参数下车体 60.0 g，括号算出来 63.6 g，重了 6.0 %。丢掉这一项，所有加速段的加速度会大 6 %，成绩快 60 ms 左右。

轮半径抵消这件事有个副作用：滑杆从 12 mm 拖到 18 mm，成绩只动 5 ms。它唯一的残余影响来自轴承力矩的力臂 `1/r_w`。这不是我没调好，是结构决定的。

## 默认参数算出来什么

输入：m = 60.0 g，CdA = 6.5 cm²，Crr = 0.0035，J = 1.30 N·s，r_w = 15.0 mm，d = 0.50 mm。

| 量 | 值 |
|---|---|
| 预测成绩 | **1.0969 s** |
| 末速度 | 17.84 m/s |
| 峰值速度 | 19.82 m/s（0.30 s 推力归零后开始掉） |
| 峰值加速度 | 409.0 m/s²（41.7 g） |
| 峰值推力 | 26.06 N |
| 有效质量 | 63.6 g（+6.0 %） |
| 积分步数 | 1098 步 |

能量账能对上，这是我最想确认的一件事：

```
推力做功 13.1977 J
 = 平移动能 9.5478 + 轮转动能 0.5729
 + 空气阻力 2.7331 + 轴承 0.2786 + 滚动 0.0412 + 导轨擦阻 0.0240
残差 −1.76×10⁻⁴
```

空气阻力吃掉推力做功的 20.7 %。这一项值得单独看，因为它和速度平方成正比，后期才发力。

## 参数敏感度

从默认值出发，一次只动一个滑杆：

| 参数 | 扫描范围 | 成绩 | 变化 |
|---|---|---|---|
| m | 50 → 75 g | 0.941 → 1.331 s | 390 ms |
| J | 0.80 → 2.00 N·s | 1.766 → 0.727 s | 1039 ms |
| CdA | 3.0 → 13.0 cm² | 1.064 → 1.163 s | 99 ms |
| d | 0 → 3.0 mm | 1.095 → 1.107 s | 12 ms |
| Crr | 0.0020 → 0.0200 | 1.096 → 1.102 s | 5 ms |
| r_w | 12 → 18 mm | 1.100 → 1.095 s | 5 ms |

推力冲量 J 是唯一真正的大杠杆，扫到两端能差 1039 ms。质量次之，390 ms。剩下的加起来不到 110 ms。

Crr 和 r_w 各自只动 5 ms。人手按秒表的重复性大概是 ±100 ms，也就是说这两个参数在比赛现场根本量不出来影响。我不打算把它们画得像很重要。

## 跟队内基准车比

基准车是上一版跑区赛那台：m 64.0 g，CdA 8.0 cm²，Crr 0.0050，J 1.31 N·s，r_w 13.0 mm，d 1.50 mm，算出来 1.1719 s。

当前默认车 1.0969 s，快 75.0 ms。按参数拆开（负号表示当前更快）：

| 参数 | 贡献 |
|---|---|
| 车体质量 | −62.3 ms |
| 迎面阻力面积 | −14.8 ms |
| 质心横向偏移 | −3.9 ms |
| 轮半径 | −1.8 ms |
| 滚动阻力系数 | −0.4 ms |
| 推力冲量 | +8.1 ms |
| **合计** | **−75.1 ms** |

六项加起来 −75.1 ms，跟直接跑出来的 −75.0 ms 差 0.1 ms。差值这么小说明在这个参数范围内模型基本是线性的，所以单参数拆解可以信。

反过来说，基准车的推力冲量其实比现在这套还高（1.31 对 1.30 N·s），成绩却慢了 75 ms。快出来的时间全在减重和减风阻上，跟推力无关。

## 模型和实际差多少

说实话，对不上，也没有能对上的数据。

校赛那次手工秒表记的是 1.15 s 上下。但秒表本身误差就有 ±0.1 s，和模型给的 1.0969 s 差 53 ms，这个差值完全埋在秒表误差里。拿它当验证等于没验证。

我知道的三个真实差距来源：推力曲线是从厂家数据手册拟合的，我们没自己的推力台；k_pin 纯属估计；实测的车会左右摆，而一维纵向模型完全不管横向。

想证伪这个模型，最快的办法是给车贴个反光片，用光电门在 10 m 和 20 m 各取一次时间。如果 10 m 处的实测比模型慢 8 % 以上，大概率是实际推力比手册低，而不是方程结构错。

模型的合理区间是 1.00–1.25 s。一旦算出区间外的数，页面会直接弹「模型超出合理区间」，把当前 t、偏快还是偏慢、以及最可能出问题的两个参数一起列出来。不会装作正常。你可以在滑杆上把 J 拖到 2.00 N·s 试试，会看到 0.727 s 和那条橙色警告。

## 已知问题

**字体是替身。** 设计稿用的是 Barlow Condensed / IBM Plex Sans / JetBrains Mono，离线环境加载不到，实际跑的是 Bahnschrift / Segoe UI / Cascadia Mono，都是 Windows 自带。换一台没装 Bahnschrift 的机器，标题会掉到 Arial Narrow，行距会松一点。中文走 Microsoft YaHei。

**k_pin = 1.5 N·m/rad 没测过。** 它决定车尾偏多少。用鱼线吊砝码从导孔侧面拉，量出转动角再反算，十分钟能测完，我们还没做。这个数直接影响「跑偏敏感度」那一栏的所有输出。

**导孔余量 0.30 mm 和另一个模型对不上。** 我们的数从导孔内径 1.2 mm、鱼线直径 0.6 mm 算出来是单侧 0.30 mm。同批另一个独立建模给出的临界横向偏移是 1.32 mm，差 4 倍。两边的驱动力矩量级是一致的（我们 12.90 mN·m，他们 18.0 mN·m），差别集中在导轨能扛住多少侧向力矩上。谁对要靠实测，现在只能说真值落在 0.3–1.3 mm 之间。

**跑偏那两栏是准静态估计，不是仿真。** 它算的是自由状态下车尾会横移多少，不做横向振动的动力学。真实的车会摆，一维模型看不见。超过导孔余量时图上会标出来，提示导孔顶死鱼线、侧向力全部转到导轨上，但模型不会自己去夹住那个数。

**F_scrub 的量级和它的真实危害不匹配。** 3 mm 偏移下它只有 0.17 N，占全部阻力的 1 % 不到，对成绩的影响是 12 ms。它真正的危害是导轨侧压力，不是让车变慢。我把它留在方程里是因为物理上它确实在，但别把它当成主要矛盾。

**Crr 和 r_w 的滑杆基本是摆设。** 各 5 ms。留着是为了完整性，不是为了让你调。

**导出图里有一层噪点。** 哈希生成的确定性噪点，不是随机数，同参数每次导出字节完全一样。它只落在暗背景上（亮度 < 44 的像素），不碰文字。作用是给纯黑加一点纸感，顺带让 PNG 有真实体积（约 970 KB）。不加的话纯色块压出来只有几十 KB。

**只在这一个 Chromium 上验证过。** Playwright 缓存的 Chromium 1223。Firefox 和 Safari 没跑过，`toBlob` 的行为可能有差别。

**移动端没适配。** 1080 宽以下是能看的，但没有专门做过触摸布局。滑杆在手机上拇指操作精度不够。

**一维模型不包含的东西：** 车轮打滑、车身俯仰、导轨接触的非线性、气瓶温度随时间的衰减、以及赛道本身的平整度。20 m 里这些大概能凑出几十毫秒，跟 Crr 的影响同量级，所以别指望这个模型的分辨率高于 20 ms。
