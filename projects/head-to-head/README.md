# 两车同跑 · Head to Head

把两台 CO₂ 车放在同一条 20 米直道上，逐毫秒积分，看到底谁先到线、差多少、差在哪一段。

这是车队内容计划的第 03 期。纯静态网页，双击 `index.html` 就能开，不联网，不上传任何数据。

上一期（`accel-curve-lab`）只跑一台车，讲的是「推力烧完之后只有阻力在咬」。
这一期把两台车并排放，问题就变成了：**多 3 克质量、多 0.01 阻力系数、少 0.2 N 推力、短 1 毫秒燃烧，加起来到底值多少个毫秒？**

答案是 **64.3 毫秒**。

---

## 为什么做这个

队里挑车的时候一直在争一件事：轻一点好还是推力大一点好。

以前只能靠感觉。现在把两条轨迹放在同一张图上，参数改一个数，时间差直接跳出来。
两个人可以指着屏幕吵，不用再互相说「我感觉」。

## 模型

### 运动方程

```
(m + Σ I_w / r_w²) · a = F_thrust(t) − ½ρ·CdA·v² − Crr·m·g
```

左边是等效惯性质量——平动质量加上四个轮子的转动惯量折算。轮子被带着转起来，这部分不能漏。

```js
// src/physics.js
export function effMass(m) {
  return m + CONST.nw * CONST.Iw / (CONST.rw * CONST.rw);
}
```

65 g 车体 + 14.88 g 折算 = **79.88 g 等效惯性质量**。
也就是说，同样 21 N 的推力，加速效果比按 65 g 算弱 **22.9%**。

两车唯一不同的就是这四个数：质量、Cd0、推力峰值、燃烧时长。其他常数共用。

### 推力曲线

半正弦爆发，烧完即零：

```
F_thrust(t) = F_peak · sin(π·t / t_burn)    t < t_burn
            = 0                              t ≥ t_burn
```

解析冲量 `I = ∫F dt = 2·F_peak·t_burn/π`。
默认的 A 车：`2 × 21 × 0.11 / π = 1.4706 N·s`。这条式子写进自检了，数值对不上会直接报错。

### 积分

RK4，定步长 `dt = 1e-3 s`，跑到位移 ≥ 20.00 m 为止。

步长减半到 `5e-4` 后成绩只变 **8.0e-9 秒**，所以 1 毫秒这档是收敛的，不是拍脑袋定的。

### 能量闭环

每一毫秒都在记账，四个数必须抵消：

```
½m_eff·v²  +  W_drag  +  W_roll  −  W_thrust  =  残差
```

默认 A 车跑完：推力做功 13.5188 J，阻力吃掉 2.0019 J，滚阻吃掉 0.1021 J，剩 11.4152 J 变成动能。
残差 **4.5e-4 J**，相对误差 3.3e-5。自检要求残差相对值 < 1e-4。

## 一个必须写下来的发现

**领先幅度先涨后跌，冲线那一刻正在缩小。**

看 `Δv = v_A − v_B` 这条曲线：

```
x = 1.05 m   Δv = 0.993 m/s   ← 峰值，就在两台车都烧完的附近
x = 5  m     Δv = 0.976 m/s
x = 10 m     Δv = 0.954 m/s
x = 15 m     Δv = 0.934 m/s
x = 20 m     Δv = 0.913 m/s   ← 冲线，只有峰值的 92 %
```

冲线处斜率 `dΔv/dx = −0.00403 (m/s)/m`，负的。

这条我一开始也没想到。直觉是「A 车一直领先，所以越到后面甩得越开」——但那是错的。

推力一烧完，两台车都在减速，减速度都是 `a = −(½ρCdA·v + Crr·m·g) / m_eff`。
关键在 **v 这一项**：A 车快，所以它挨的阻力和速度成正比地更大。**领先的车减速更狠**，差距就被一点点啃回去。

换句话说，A 车是「提速提得快」，不是「后段还能继续甩开」。它赢的那 64 毫秒，几乎全是在前 1 米内挣到的，之后 19 米一直在吐回去。

这条结论反过来也成立：把两车参数对调，斜率翻成 `+0.00403`，一模一样，只是正负号换了个方向。所以这不是数值噪声。

**为什么这条值得写下来：** 如果只按「谁的参数好谁赢」来选车，会低估轻车的价值。轻车的优势不只出现在起跑，还贯穿整段滑行——它一直在把差距往回挣。

## 已知问题

这些是真的没做好的地方，不是客套。

1. **B 车是我调出来讲故事的，不是真实对手。** 我试了 5 组参数才定下这一组。最初一组跑出 1.5568 s、差 368 毫秒——那不是比赛，那是一台车在等另一台。为了让差距落在「看得出来但不算碾压」的 60–70 毫秒区间，我手动调了质量、Cd0、推力和燃烧时长。**换句话说，这组参数是为了让画面好看而选的，不是从两台真实赛车量出来的。** 如果你有实测数据，把 `state.A` 和 `state.B` 换掉重跑就行，图会自动重算。

2. **两车共用一个 Cd0 常数和同一个迎风面积。** 真实情况下车头形状、姿态角、离地间隙都会影响 CdA，而且两车不可能完全一样。这里 A 和 B 的 CdA 是 `Cd0 × 同一个 A` 算出来的，等于假设了两车迎风面积相同。

3. **没有任何随机性，所以真实比赛一定比这个乱。** 两台真车的 CO₂ 气瓶压力不可能一致，气瓶温度差 5 °C 就能让推力差几个百分点。真实对拉的差距会比我算的这个更没规律。这个模型给出的 64.3 毫秒应该理解成「参数差异带来的系统性差距」，不是「实测定会差这么多」。

4. **推力曲线是猜的，而且是两车共用同一个形状。** 半正弦没有任何实测依据，纯粹因为它比矩形波更合理一点。真实气瓶是尖峰然后快速衰减，和半正弦差得不小。这条直接影响所有绝对数值。

5. **没有抬头力矩、没有升力、没有轮子打滑。** 车头被气流抬起会改变接地法向力，进而改变滚阻和牵引极限；轮子在起步瞬间打滑会吃掉一部分推力。这三样在模型里全都没有。26.8 g 的峰值加速度如果真实存在，起步打滑几乎是一定会发生的——所以真实成绩应该比这里差，而模型不会告诉你差多少。

6. **`t_burn` 只差 1 毫秒时，RK4 在 1 毫秒步长下可能分辨不出来。** B 车燃烧 109 ms、A 车 110 ms，差 1 毫秒正好等于积分步长。推力在 `t < t_burn` 区间取半正弦值，边界会落在步长之间。我用步长减半验证过总成绩收敛（8e-9 秒），但没有单独验证这 1 毫秒的差异是否被正确解析——理论上它会被抹平一部分。

7. **「冲线车距」的定义是我挑的。** 我取的是「先冲线的车到线瞬间，另一台车还差多少米」，A 车赢时算 `20 − x_B(t_A)`。也可以定义成「B 冲线时 A 已经跑了多远」，那是另一个数（还得外推 A 车冲线后的滑行）。我选了前者，因为它是唯一不需要外推的定义。顺带一提，我第一版用的是 `|Δt| × 平均速度` 的近似式，给出 1.057 m，和精确值 1.030 m 差了 2.6%——这个近似被换掉了。

`墨量 27.22% / 122 色` 这两个数是门禁直接用 `getImageData` 量出来的，不是自己报的。空脚手架一般在 1.4% / 16 色左右，所以这两个阈值（8% 和 48）能真的拦住空壳。

门禁里还有四条本项目专属的物理断言，任何一条不过就不出 `GATE OK`：

- **同参数两车成绩必须完全相等**（差 0 秒，不是差一点点）
- **质量加重 20% 成绩必须变差**
- **等阻力只改质量时，冲线处斜率必须是负的**
- **Δv 曲线采样点数必须是 401**（0.05 米一格）

第一条是故意写成精确相等的。两车走同一条代码路径、同一个步长序列，结果必须逐位相同；如果哪天出现浮点漂移，这条会立刻炸。

## 操作

- 8 个滑杆：两车各自的 质量 / Cd0 / 推力峰值 / 燃烧时长，拖动即重跑整场比赛
- 「重跑一次」重新播放动画
- 「导出 9:16」出 1080×1920 竖版
- 左侧大数字：跑的过程中显示实时领先距离（米），到线后切换成成绩差（毫秒）

画布本身就是成片，不是预览。CSS 缩到 540×960 只是为了在桌面上一屏放得下，导出的永远是 1080×1920。
