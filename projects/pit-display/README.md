# 维修区计时牌 · pit-display

> 在线版：https://zhuka4141-cmyk.github.io/stem-racing/projects/pit-display/
两张成绩卡：1080×1920 的竖版（Reels）和 1080×1350 的 4:5 封面。车号、队名、七段数码管写的成绩、名次牌、
六轮柱状图、四格读数、记录口径、底条，七条带在两块画板上各排一遍，纵向尺寸不同但带序一致。

起因很具体：队里发成绩一直是手写 A4 拍一张照。手写的 1.1 和 1.4 在手机上分不清，小数点位也对不齐，
转发两轮就有人说"你们那 1.142 是不是 1.412"。所以时间不用字体画，用七段数码管一段一段拼出来，
位数天然对齐，缩到 200 px 宽也认得出。

## 怎么跑

双击 `index.html`。不用服务器，不用联网，不读任何外部资源。
底下六个输入框：车号、队名、成绩、名次、参赛数、头名成绩。改哪个，上面的画布立刻重排。

**这些数字里，除了 20.000 m 和七段数码管的几何，其余全是编的。** 六轮成绩、队名、车号、参赛 18 支、

## 怎么做的

**不是 Canvas2D 画的，是先拼一段 SVG，再光栅化到 canvas 上。** 用 SVG 是因为 `<text>` 能拿到亚像素定位、
线宽可以给 1 px、`<pattern>` 画斜线不糊。光栅化走 `data:image/svg+xml` → `Image` → `drawImage`，
`file://` 下不需要服务器。看见的就是导出的那张图，测像素也读同一块 canvas。

**时间不是字体，是几何。** 每个数字由七个六边形拼出来，见 `segShapes()`：横段 `a/g/d`、竖段 `b/c/e/f`
各是一个六点多边形，两端收尖用 `k = t/2`，所以斜面正好 45°。没点亮的那几段照样画，
`fill-opacity="0.09"` 留一点余辉——真实数码管被环境光打亮就是这个观感，0.09 是照着调的，不是测的。

宽度是算出来的：`segWidth('1.142')` = 4 × (156 + 14) + 34 − 14 = **700 px**，左端从 x=48 起，
右端落在 **748**。名次牌左边界 `RANK_X = 792`，还剩 44 px。`selfTest()` 里有一条断言就拿这两个数比。

版面分七条带，y 全是硬编码：

```
A 抬头 74–112    B 车号/队名/车道 124–286    C 成绩+名次牌 316–672
D 六轮柱状图 708–964    E 四格读数 984–1118    F 口径四行 1148–1254
G 斜线警示条 + 底条 1284–1314
```

柱状图纵轴是截断的：`lo = floor(最好×100)/100 − 0.01`，`hi = ceil(最差×100)/100 + 0.01`，
默认得到 1.13–1.23 s。这样 0.072 s 的极差才能在 192 px 高度里看出差别，代价是柱子的绝对高度没有意义，
右上角印的"纵轴 1.13–1.23 s 截断"就是提醒这件事。六根柱子均分 922 px，每格 153.67 px，柱宽取 0.60 倍即 92.2 px。

只有一个橙色 `#E8590C`，用在三处：抬头小方块、连续点亮的那几段、最好那一轮。

## 已知问题

按"会让人看错数"到"只是不爽"排。

1. **口径带第 3、4 条跟代码对不上。** 第 3 条写"第 6 轮 1.149 s 记在册但未参与平均值计算"，
   但 `derive()` 里 `mean` 和 `sd` 都把六轮全算进去。按六轮算标准差 0.024568，按前五轮 0.025160，
   差 2.4%。四舍五入到三位小数两边都是 0.025，所以卡面上看不出来，这是巧合不是设计。
   更要命的是这张牌上根本没显示平均成绩：写"未参与平均值计算"时，说的是一个不存在的数。
   第 4 条"同秒按车号先后"同理，代码里没有任何 tie-break 逻辑。

2. **成绩和六轮是两个互不相干的数据源。** 成绩读 `state.time`（能改），柱状图和"逐轮最好"读
   `state.runs`（改不了）。把成绩填 1.300，时间带显示 1.300 s，右边"逐轮最好"还是 1.142 s，
   平均速度变成 15.385 m/s。同一张牌上总成绩比它自己声称的最快一轮还慢，界面上没有任何提示。

3. **"第 N 轮 / 共 N 轮"永远同一个数。** 代码是
   `第 ${pad(state.runs.length)} 轮 / 共 ${pad(state.runs.length)} 轮`，两处都取 `runs.length`，
   所以永远印"第 06 轮 / 共 06 轮"。它想表达"当前跑到第几轮"，但那个量从来没被存过。

4. **长队名会压到车道号，实测交叠 9.6 × 37.7 px。** 队名框没有 `maxlength`。
   实测"钢筋混凝土超长队名测试样本"右端到 x=993.2，右上角车道号"02"从 x=983.6 起，
   y 方向 164–218 与 168–205.7 重叠。"车队 LANE"那行从 966.6 起，更早就会撞。
   `layout.mjs` 能查这种重叠，但它跑默认短队名，测不到。

5. **成绩没有上界，超过 9.999 s 七段就压进名次牌。** 输入框只钳了下界 `Math.max(0.5, ...)`。
   五个字符宽 700 px（右端 748），六个字符宽 870 px（右端 918），名次牌左边界在 792。
   填 10.000 就压进去 126 px，平均速度还会印出 2.000 m/s 这种 20 m 直线上不可能的数。
   `selfTest()` 里有 `state.time < 5` 会拦，但它只在门禁里跑，界面不跑。

6. **"与头名差距"把负值也显示成"— 头名 —"。** 条件是 `d.gapToLead > 0.0005`，
   `gapToLead = time − lead`。默认两个都 1.142 所以显示"— 头名 —"，没问题。
   但把成绩填 1.100、头名填 1.142（你已经更快），差值是 −0.042，代码照样写"— 头名 —"。

7. **9:16 和 4:5 现在是两张真图，但 9:16 只能在导出里看到。** 两块画板
   （`board916` 1080×1920 / `board45` 1080×1350）每次都一起重画，`exportPNG` 出竖版、
   `exportCover` 出封面，字节不同，门禁会拿两张各自量墨量和空带。但屏幕上挂的还是 4:5 那块，
   想直观看竖版只能导出。竖版的纵向骨架是 `L916` 那张表：抬头/车号/时间/逐轮/读数/口径/底条
   七条带重新分配 1920px，数码管从 290 拉到 400、名次牌从 204 拉到 300、柱状图从 192 拉到 392，
   不是把 4:5 上下补白。

8. **门禁不验画面，只验字节数。** `gate.mjs` 里没有 `getImageData`，量不到墨量和色彩数。
   另外几个项目用的是带墨量断言的硬化版（安全区墨量 ≥ 8%、色彩 ≥ 48 种）。
   要量画面得单独跑 `visual.mjs`，而它只报告、不判定失败。

9. **声明安全区比实际画到的范围小。** `__app.safe` 写 y 60–1290，但底条基线在 1314、
   斜线警示条占 1284–1300，都在安全区外。`visual.mjs` 用这个 `safe` 算墨量，底部那一条没被统计。
   `selfTest()` 查底条的那条是 `geo.footBaseline + 8 > 1322`，1314 + 8 正好等于 1322，零余量通过。

10. **柱状图刻度的 `+0.0099` 是魔法数。** 网格线实际画在 1.1399 / 1.1599 / 1.1799 / 1.1999 / 1.2199，
    标签写 1.14 / 1.16 / 1.18 / 1.20 / 1.22。差 0.0001 s，在 0.10 s 跨 192 px 下约 0.19 px，
    看不出来，但标签和线确实没对齐。当初加这个数是躲浮点误差，没想清楚。

## 目录

```
pit-display/
├─ index.html            六个输入框 + 1080×1350 画布
├─ src/
│  ├─ main.js            七段几何、七条带排版、derive()、selfTest()
│  ├─ svg-artboard.js    SVG 拼装 + 光栅化（来自 shared/）
│  └─ reel-export.js     PNG 导出（来自 shared/）
├─ dist/app.js           esbuild 打的 IIFE
├─ design-tokens.css     来自 shared/
├─ qa/                   page.png · shot-1080x1350.png
└─ tests/                gate · visual · fonts · platform · layout · ascii · shot
```

`src/svg-artboard.js`、`src/reel-export.js`、`design-tokens.css` 每次 `node build.mjs`
都会从 `_stemlab/shared/` 重新拷一遍。**改项目里的会被下一次构建冲掉**，要改去改 shared 那份。

`dist/app.js` 打成 IIFE 不用 ESM，是因为 `file://` 下 `<script type="module">` 会被 CORS 拦掉。
