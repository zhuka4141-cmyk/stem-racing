# race-calendar —— 赛历

> 在线版：https://zhuka4141-cmyk.github.io/stem-racing/projects/race-calendar/
把一整个赛季 9 场比赛排成一条时间线，已完赛 / 进行中 / 待开赛三种状态颜色不同，每场带倒计时，导 1080×1920。

赛程写在 `src/races.js` 里。**状态不用写**，页面按这台电脑的日期自己算。倒计时也只认本机时间，不查任何时间服务器。

---

## 怎么跑

```
node build.mjs
node tests/gate.mjs
node tests/visual.mjs
node tests/fonts.mjs
node tests/ascii.mjs
node tests/shot.mjs
```

改赛程：编辑 `src/races.js`，重新 `node build.mjs`。

## 三种状态怎么算的

```js
今天 < start        → 待开赛
今天 > end          → 已完赛
start ≤ 今天 ≤ end  → 进行中
```

只在日期层面比较，把 `YYYY-MM-DD` 换算成「从 1970 起第几天」再相减：

```js
function dayNum(ymd) {
  const [y, m, d] = ymd.split('-').map(Number);
  return Math.round(Date.UTC(y, m - 1, d) / 86400000);
}
```

用 `Date.UTC` 而不是 `new Date('2026-10-22')`，是因为后者在部分浏览器里按 UTC 解析，东八区会差一天。这里两边都当纯日期算，不做时区换算。

倒计时：
- 待开赛 → `还有 23 天`
- 进行中 → `第 1 / 2 天`
- 已完赛 → `40 天前`

## 卡面

- 0–240 是 IG 状态栏死区，只放细线和 5.5% 透明度的 `SEASON` 水印
- 240 起：橙色短杠 + `STEM RACING` + 66px「赛历」，右上角是总场次，左上角是今天的日期
- 412–486 三列：赛季 / 今天 / 下一场
- 500–1232 是时间线。x=72 一根竖脊线，每场在脊线上一个节点：
  - 进行中 → 13×13 实心橙方 + 整行 `rgba(232,89,12,0.13)` 底色
  - 待开赛 → 8×8 空心白方
  - 已完赛 → 8×8 空心灰方，赛事名降成 55% 白
- 1232 起汇总：已完赛 / 进行中 / 待开赛 三个数
- 1394 起页脚

行高自适应：`(1232-500) / 场次`，封顶 92px。9 场算下来是 81px。

## 门禁怎么证明状态不是写死的

光验「今天显示 2/1/6」证明不了什么——那可能只是代码里写死了三个数字。所以门禁把日期**推着走**：

1. 钉在 `2026-10-22` → 应该是 2 已完赛 / 1 进行中 / 6 待开赛，进行中的是「内部计时 + 轴检」，显示 `第 1 / 2 天`
2. 推到 `2026-12-05` → 已完赛变 4，进行中变成「区赛 决赛」，`第 1 / 1 天`
3. 推到 `2027-07-01` → 9 场全部已完赛，此时筛「待开赛」是 0 场
4. 刷新 → 必须回到真实的本机日期，和 `new Date()` 拼出来的 `YYYY-MM-DD` 一致

第 3 步顺带提供了空结果状态，量墨量，要求 ≥ 8%。实测 26.26%。

「今天」是用 `new Date(2026, 9, 22, 12, 0, 0)` 在浏览器里构造的——本地时间 + 中午，避开任何跨日边界。

## 门禁在查什么

通用部分在 `tests/core.mjs`：7 条禁用 API 静态扫描、5 个运行时插桩计数器必须全 0、导出 PNG 魔数 + 字节数、无外站资源、无外网请求、两张截图。

本项目自己的：

| # | 断言 |
|---|---|
| 1 | 钉住日期后 2/1/6，加起来等于 9，`selfTest()` 通过，画布 1080×1920 |
| 2 | 进行中那场名字是「内部计时 + 轴检」，两天赛事显示成 `10/22–10/23`，倒计时 `第 1 / 2 天` |
| 3 | 下一场倒计时 `还有 23 天`；第一场 `40 天前` |
| 4 | 推到 12-05 / 2027-07-01，状态跟着走 |
| 5 | 筛「待开赛」0 场时墨量 ≥ 8% |
| 6 | 四个筛选各自的行数 2/1/6/9 |
| 7 | 刷新回真实日期、回「全部」 |
| 8 | 切换筛选后汇总跟着变，抬头和三列加起来都等于显示场次 |
| 9 | 筛到 0 场时汇总三列全是 0，不许出 NaN / Infinity |

## 实测

| 项 | 值 |
|---|---|
| `dist/app.js` | 17 KB |
| 竖版 1080×1920 | 162 KB |
| 封面 1080×1350 | 132 KB |
| 安全区整体墨量 | 35.86% |
| 安全区 150px 连续死区 | 0 处 |
| 空结果状态墨量 | 26.24% |
| 页面用到的不同字符 | 164 个 |
| MONO / DISP 各查 | 162 字，缺 0 |
| 门禁静态规则 | 7 条，0 命中 |
| 全程网络请求 | 8 条，全部本地协议 |

墨量 35.86% 是五张卡里偏高的，主要来自隔行底纹（`rgba(242,240,235,0.07)` 叠在 `#0b0b0c` 上亮度约 27，过了 24 的墨量阈值）。这是有意的：不铺底纹的话，纯文字卡的墨量只有 2–3%，远低于 8% 的下限，卡面也会显得空。

## 已知缺陷

1. **「今天」只认本机日期。** 电脑时间错了，倒计时就全错，而且卡上不会有任何提示。不联网校时是这个项目的硬要求，但「不校时」和「时间错了也不知道」是两件事，后者没处理。

2. **赛季结束就没有下一页。** 日期写死在常量里，到 2027 年 7 月之后整张卡全是「已完赛」，倒计时全是「N 天前」。没有翻到下一季的入口，得改代码。

3. **只认日期区间，不认改期。** 比赛临时改到别的日子，卡上不会知道，还是按常量里的 `start`/`end` 算。

4. **「还有 N 天」按日历日算，不是按小时。** 10-23 23:59 和 10-24 00:01 都显示「还有 1 天」，实际差两分钟。要精确到小时就得处理时区，这轮没做。

5. **不显示周几。** 9 场只有 `mm/dd`，家长看不出哪场在周末。加个「周六」是几行的事，但 81px 一行里已经没地方放了。

6. **日期是我按校历编的。** 场次、地点、备注都是假的，不是真实赛事通知。发之前必须换成真的。

7. **筛选和汇总曾经对不上账，已修。** 以前抬头场次直接写 `RACES.length`，三列汇总和侧栏读数
   各自 `build(state.now)` 重算全量，只有最底下的「显示 N / 9」跟着筛选走。筛「待开赛」时
   表上 6 行、汇总还是 2 / 1 / 6，两个数字摆在一起对不上账。
   现在这五处统一走 `countsOf(state.rows)`，抬头也改成 `state.rows.length`：筛「待开赛」时
   抬头写 6、三列是 0 / 0 / 6，加起来正好等于「显示 6 / 9」。筛到 0 场时抬头写一个灰掉的 0，
   三列全 0，底下印「显示 0 / 9 场 · 这个筛选下没有比赛」，不会出 NaN 或 Infinity。
   门禁补了四条断言，把修复撤掉会红 8 条。

8. **空状态文案有个没兜住的 key。** `drawEmpty()` 里写的是 `{ done:..., live:..., next:... }[state.filter]`，没有 `all` 这个键。现在筛「全部」不可能出现 0 行，所以碰不到；但哪天 `races.js` 被清空，卡上会印出「没有undefined的比赛」。

9. **4:5 封面切掉眉标。** 封面居中裁切，取源图 y 285–1635，y=240 的橙色短杠和 y=276 的 `STEM RACING` 不在封面里。
